# E935 (European 2.0 16V) notes

E935 is the ROM ID of the European 1G Eclipse 2.0 16V non-turbo ECU
(MMC MD169144, MEC E2T36583). The same ECU is reported in the Galant E33 GTi 16V.
No public EPROM dump or disassembly exists as far as we know, so the address
map below is verified one address at a time. This page collects what we find.

All observations: 1991 Eclipse GS, Swiss spec, 2026-11-13.

## The line is inverted

The E935 speaks the same request/reply protocol as US ECUs ([protocol.md](protocol.md)),
at the same 1953 baud, but with inverted levels:

| | US ECUs | E935 |
|---|---|---|
| Pin 1 idle, diagnostic mode | High (the ECU pulls it up) | **0 V, floating** |
| Start bit, 0 bits | Low | **High (12 V, driven by the ECU)** |
| 1 bits, stop bit | High | **Low** |
| Wiring | 12 V or 5 V wiring | [Inverted wiring](wiring.md#inverted-wiring-e935) |

The E935 has a single output stage on pin 1 that can only drive the line high.
It uses this stage for the flash codes too. The proven
[MMCd-Go](https://github.com/kevin-buckham/MMCd-Go) cable has only a 10k
pull-down on pin 1, so US ECUs must hold pin 1 high themselves.

## Hardware observations

| Item | Observed |
|---|---|
| Pin 1, key on, no bridge | 12 V flash-code pulses |
| Pin 1, key on, pin 10 bridged | 0 V, floats: 1.6 MΩ and 6.3 MΩ to pin 12 (both probe directions) |
| Pin 10, ignition on | ~12 V (pulled up through the ECU) |
| Populated connector pins | 1, 5, 6, 10, 11, 12 |
| Requests in US polarity | Clean echo, no reaction at all, also no edges on the line |
| Requests in inverted polarity | The ECU replies 0.4–12 ms after the request ends |
| Line capacitance | About 50 nF, from edge timing. A 10k pull-down makes the falling edges about 0.9 ms late, which corrupts single 0-bits. 2k gives clean edges. |
| Request level | 3.3 V high caused misread requests. 5 V high gave 50 of 50 clean replies. |

## Version byte (0xFD)

Not read. The E935 profile does not send 0xFD: one bit error turns it into
0xFC (an actuator test) or 0xFF.

## Address map verification

Read with `firmware/sniffer` and decoded by mid-bit sampling, then confirmed with
`npm run dashboard:e935`. Every reply below came back the same in all runs.

| Address | US meaning | Reply | US scaling | E935 status | How verified |
|---|---|---|---|---|---|
| 0x14 | Battery voltage (×0.0733 V) | 0xA8 engine off, 0xC7 running | 12.3 V, 14.6 V | **confirmed** | Fluke: 12.46 V right after key off; charging voltage while running |
| 0x17 | Throttle position | 0x17 closed, 0xFF fully pressed | 9 %, 100 % | **confirmed** | Gas pedal test, engine off, in the sniffer and the dashboard |
| 0x21 | Engine speed (×31.25 rpm) | 0x00 off, 0x2A–0x2B cold idle | 0 rpm, 1313–1344 rpm | **confirmed** | Tachometer: about 1400 rpm at cold idle |
| 0x07 | Coolant temp | 0x9F cold, falls steadily after the start | about 25 °C, rising (approximate curve) | live, scaling unverified | Check against a thermometer |
| 0x00 | Flags (A/C clutch 0x20) | 0xBF | – | unknown | Not on the allowlist |
| 0x38, 0x39, 0x3B, 0x3C | Fault code words | active 0x0000, stored 0x0008 | stored: code 14 (throttle position sensor) | read, mapping unverified | Cross-check with the flash codes (pin 10 open, meter on pin 1) |
| 0x06 | Timing advance (−10 °) | – | – | not read | |
| 0x02 | Switch flags (idle, P/N, A/C, PS) | – | – | not read | |
| 0xCA | Clear fault codes | – | – | not sent | Clear codes is off in the E935 profile |

## Allowlist

The E935 profile sends only these addresses: 0x07, 0x14, 0x17, 0x21, 0x38, 0x39,
0x3B and 0x3C. The firmware is the hard gate (`allowed()` in
`firmware/dsm_bridge/dsm_bridge.ino`); `E935_ALLOWED` in `src/mmcd.ts` mirrors it.
The dashboard shows each sensor's status from `E935_STATUS` in `src/mmcd.ts`.

### Candidates

`firmware/sniffer` may also read the candidates: every US sensor, flag and fault
address that is at least two bit errors away from 0xCA, 0xF1–0xFC, 0xFE and 0xFF.
`E935_CANDIDATES` in `src/mmcd.ts` derives the list; the sniffer's `CANDIDATES`
must match it, and the self-test checks this. 0xFD is one bit error from 0xF5,
0xFC and 0xFF, so it is no candidate.

### To add an address

1. Upload the sniffer: `npm run fw -- sniffer`.
2. Watch the candidate live: `npm run verify -- 06,3A --log verify.csv`.
3. Confirm the value against a real measurement. The checklist below lists one per address.
4. Add it to `allowed()`, `E935_ALLOWED` and `E935_STATUS`, and record the evidence in the table above.
5. Upload the bridge again: `npm run fw -- bridge --wiring inverted`.

## Next session at the car

Order: static first, then dynamic. Keep the [connect order](wiring.md#inverted-wiring-e935).
Expected values are typical for US ECUs; the reference test is what counts.

Before you go:

- [ ] Laptop charged, Fluke, thermometer for the coolant hose, timing light if available
- [ ] `npm run fw -- sniffer` works on the bench (car pins disconnected)

Key on, engine off, cold engine:

- [ ] `npm run verify -- 3A,07,15,02,13`
- [ ] 0x3A intake air temp: close to the coolant temp and to the outside temperature
- [ ] 0x15 barometer: compare with the air pressure at your altitude (weather service), about 0.95 bar
- [ ] 0x02 switch flags: the idle switch bit toggles when you press the pedal
- [ ] 0x13 O2 sensor: about 0 V and steady

Engine idling, cold:

- [ ] `npm run verify -- 21,06,1A,29,16,1D,26,02,00`
- [ ] 0x06 timing: timing light, or plausibly 5–15° BTDC
- [ ] 0x1A MAF frequency: about 25–40 Hz at idle, rises with rpm
- [ ] 0x29 injector pulse width: about 2–3 ms at idle
- [ ] 0x16 ISC steps: rise when you turn the wheel, switch on the lights or the A/C
- [ ] 0x02 flags: power steering bit when you turn the wheel, A/C switch bit with the A/C button
- [ ] 0x00 A/C clutch: bit 0x20 with the A/C on
- [ ] 0x1D accel enrichment: 0 at idle, jumps when you blip the throttle
- [ ] 0x26 knock sum: 0 at idle

Engine idling, warm (thermostat open, about 10 minutes):

- [ ] `npm run verify -- 07,13,0C,0D,0E,0F`
- [ ] 0x07 coolant: thermometer on the upper hose, about 85–90 °C
- [ ] 0x13 O2 sensor: switches quickly between about 0.1 and 0.9 V
- [ ] 0x0C–0x0F fuel trims: around 100 % (raw about 0x80)

Afterwards:

- [ ] Add each confirmed address as described above, and keep the `verify.csv` logs as evidence
- [ ] `npm run fw -- bridge --wiring inverted`, then check the new sensors in `npm run dashboard:e935`

## Later

- **Explore and RAM reads on the E935** (0x40–0xF0): reads on US ECUs, but each
  request carries a small misread risk. Decide after the checklist above, based
  on the misread record.
- **Datalogging while driving:** CSV recording works. Secure the laptop, keep
  the wires short, and do not watch the screen while driving.
