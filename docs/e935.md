# E935 (European 2.0 16V) notes

E935 is the ROM ID of the European 1G Eclipse 2.0 16V non-turbo ECU
(MMC MD169144, MEC E2T36583). The same ECU is reported in the Galant E33 GTi 16V.
No public EPROM dump or disassembly exists as far as we know, so the address
map below is verified one address at a time. This page collects what we find.

All observations: 1991 Eclipse GS, Swiss spec, 2026-11-13.

## The line is inverted

The E935 speaks the same request/reply protocol as US ECUs ([protocol.md](protocol.md)),
at the same 1953 baud, but with inverted levels:

| | US ECUs | E935 |
|---|---|---|
| Pin 1 idle, diagnostic mode | High (the ECU pulls it up) | **0 V, floating** |
| Start bit, 0 bits | Low | **High (12 V, driven by the ECU)** |
| 1 bits, stop bit | High | **Low** |
| Wiring | 12 V or 5 V wiring | [Inverted wiring](wiring.md#inverted-wiring-e935) |

The E935 has a single output stage on pin 1 that can only drive the line high.
It uses this stage for the flash codes too. The proven
[MMCd-Go](https://github.com/kevin-buckham/MMCd-Go) cable has only a 10k
pull-down on pin 1, so US ECUs must hold pin 1 high themselves.

## Hardware observations

| Item | Observed |
|---|---|
| Pin 1, key on, no bridge | 12 V flash-code pulses |
| Pin 1, key on, pin 10 bridged | 0 V, floats: 1.6 MΩ and 6.3 MΩ to pin 12 (both probe directions) |
| Pin 10, ignition on | ~12 V (pulled up through the ECU) |
| Populated connector pins | 1, 5, 6, 10, 11, 12 |
| Requests in US polarity | Clean echo, no reaction at all, also no edges on the line |
| Requests in inverted polarity | The ECU replies 0.4–12 ms after the request ends |
| Line capacitance | About 50 nF, from edge timing. A 10k pull-down makes the falling edges about 0.9 ms late, which corrupts single 0-bits. 2k gives clean edges. |
| Request level | 3.3 V high caused misread requests. 5 V high gave 50 of 50 clean replies. |

## Version byte (0xFD)

Not read. The E935 profile does not send 0xFD: one bit error turns it into
0xFC (an actuator test) or 0xFF.

## Address map verification

Read with `firmware/sniffer` and decoded by mid-bit sampling, then confirmed with
`npm run dashboard:e935`. Every reply below came back the same in all runs.

| Address | US meaning | Reply | US scaling | E935 status | How verified |
|---|---|---|---|---|---|
| 0x14 | Battery voltage (×0.0733 V) | 0xA8 | 12.3 V | **confirmed** | Fluke: 12.46 V right after key off |
| 0x17 | Throttle position | 0x17 closed, 0xFF fully pressed | 9 %, 100 % | **confirmed** | Gas pedal test, engine off, in the sniffer and the dashboard |
| 0x21 | Engine speed (×31.25 rpm) | 0x00 | 0 rpm | plausible | Engine off; check with the engine running |
| 0x07 | Coolant temp | 0x9F | about 25 °C (approximate curve) | plausible | Cold engine; check against a thermometer |
| 0x00 | Flags (A/C clutch 0x20) | 0xBF | – | unknown | Not on the allowlist |
| 0x38, 0x39, 0x3B, 0x3C | Fault code words | active 0x0000, stored 0x0008 | stored: code 14 (throttle position sensor) | read, mapping unverified | Cross-check with the flash codes (pin 10 open, meter on pin 1) |
| 0x06 | Timing advance (−10 °) | – | – | not read | |
| 0x02 | Switch flags (idle, P/N, A/C, PS) | – | – | not read | |
| 0xCA | Clear fault codes | – | – | not sent | Clear codes is off in the E935 profile |

## Allowlist

The E935 profile sends only these addresses: 0x07, 0x14, 0x17, 0x21, 0x38, 0x39,
0x3B and 0x3C. The firmware is the hard gate (`allowed()` in
`firmware/dsm_bridge/dsm_bridge.ino`); `E935_ALLOWED` in `src/mmcd.ts` mirrors it.

To add an address:

1. Check that it is a read on US ECUs ([protocol.md](protocol.md)).
2. Check that it is at least two bit errors away from 0xCA, 0xF1–0xFC, 0xFE and 0xFF.
3. Read it with `firmware/sniffer` and confirm the value against a real measurement.
4. Add it to both lists and to the table above.
